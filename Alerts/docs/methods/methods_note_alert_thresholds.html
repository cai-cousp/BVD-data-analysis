Methodological Note — Weekly Alert Thresholds, EVD17 Response

Documenting the implemented threshold synthesis and its assumptions

Published

July 18, 2026

0.1 Purpose

This note documents the threshold-generation workflow implemented in R/01_alert_thresholds.R. It describes how the script derives weekly alert thresholds per health zone (HZ) from three sources: baseline mortality, the historical Beni alert dataset, and case-derived expectations from the current line list.

The operational question is:

Given the population size and current epidemiology of a health zone, how many validated alerts for cases and deaths in a week are unusual enough to warrant review?

The script combines multiple imperfect sources because no single method is reliable in this setting. The goal is to produce a defensible threshold table and preserve the intermediate estimates used to build it.

0.3 Approach A: Baseline mortality

This approach converts crude mortality into an expected weekly death count per HZ.

For a health zone with population \(P\) and crude mortality rate \(m\) per 1,000 per year, the script computes:

\[ E[D_w] = \frac{P \times m}{1000} \times \frac{7}{365} \]

The lower and upper thresholds are set as fixed 10% bounds around this expected weekly value in the implemented code:

\[ T_A^{lower} = 0.9 \times E[D_w], \qquad T_A^{upper} = 1.1 \times E[D_w] \]

These are death-only thresholds.

0.4 Approach B: Beni historical benchmark

This approach uses validated alerts in the historical Beni dataset as an empirical reference.

The implemented workflow is:

  1. Restrict to validated alerts.
  2. Aggregate by HZ and epiweek.
  3. Compute positivity as:

\[ \text{positivity} = \frac{\text{positive samples}}{\text{sampled validated alerts}} \]

For Beni, sampled alerts are proxied by non-missing laboratory results. 4. Define optimal weeks as those with positivity below 10%. 5. Within optimal weeks, compute weekly alert rates per 100,000 population. 6. Retain HZs with at least 50 validated alerts and case-alert rates in the top quartile. 7. Use the Beni reference values from the best-performing HZs as the benchmark rates. 8. Scale those rates to each target HZ population.

The benchmark values are stored as case and death rates, then converted to HZ-specific alert counts by multiplying by population / 100,000.

0.5 Approach C: Case-derived expectations

This approach uses the current line list to estimate the number of alerts that should be expected from the outbreak context in each HZ. It is the only approach that adapts to the current epidemic state of each zone.

Approach C chains five building blocks, documented below:

  1. Epidemiological parameters estimated per HZ (CFR, back-calculated CFR, growth rate, \(R_t\), SAR).
  2. Detection rate from epi-links — the proportion of confirmed cases found through active contact tracing.
  3. Detection rate from back-calculation — the proportion of true cases actually detected, inferred from observed deaths.
  4. Combination of the two detection estimates into a single rate used to back-calculate true case counts.
  5. Poisson offset multiplier model that translates estimated true cases into expected validated-alert counts, producing \(\beta_c\) and \(\beta_d\).

The case-derived thresholds are therefore window-specific and HZ-specific, and they are merged with the baseline and Beni-derived thresholds in the final synthesis table.

0.5.1 C.1 Epidemiological parameters

For each HZ, the script estimates:

Parameter Function Definition
CFR (cfr_used) compute_cfr_by_hz() Deaths among confirmed cases / confirmed cases; pooled CFR used when HZ has < 5 confirmed cases
Back-calculated CFR compute_cfr_backcalc_by_hz() See C.3
Growth rate \(r\) compute_growth_rate_by_hz() Exponential growth rate from incidence::fit() in rolling 7-day windows; pooled across all HZs as fallback
\(R_t\) compute_rt_hz() EpiEstim parametric SI (mean 12, sd 5 days) over last 21 days of onset dates; pooled \(R_t\) as fallback for sparse HZs
SAR Derived \(R_t / k\) where \(k = 10\) contacts per case; capped and coerced to 0.1 when missing
Expected deaths Derived \(\hat{C}_{\text{true}} \times \text{CFR}\)
Expected secondary cases Derived \(\hat{C}_{\text{true}} \times k \times \text{SAR}\)

0.5.2 C.2 Epi-link detection method

The epi-link method estimates the detection rate from the proportion of confirmed cases that were found through active contact tracing (marked by an epidemiologic link), among confirmed cases with valid epidemiologic-link data.

\[ \rho_{\text{epilink}} = \frac{n_{\text{epilink}}}{n_{\text{conf, valid epilink}}} \]

where \(n_{\text{epilink}}\) is the number of confirmed/positive cases with alert_lien_epidemiologic == "Oui", and \(n_{\text{conf, valid epilink}}\) is the number of confirmed cases with non-missing epidemiologic-link data.

When \(n_{\text{conf, valid epilink}} < 5\), the HZ-specific rate is replaced by the pooled (all-HZ) detection rate:

\[ \rho_{\text{epilink, pooled}} = \frac{\sum_{\text{all HZ}} n_{\text{epilink}}}{\sum_{\text{all HZ}} n_{\text{conf, valid epilink}}} \]

The under-detection rate is \(1 - \rho_{\text{epilink}}\).

Rationale. A high proportion of epi-linked cases suggests active case-finding is working well; a low proportion suggests many cases are arriving through passive routes and may reflect under-detection.

0.5.3 C.3 Back-CFR detection method

The back-CFR method estimates the detection rate from observed deaths, in two stages.

Stage 1 — Back-calculated CFR. The back-calculated CFR enlarges the denominator beyond confirmed cases alone by including eligible deaths that were never laboratory-confirmed:

\[ \text{CFR}_{\text{backcalc}} = \frac{D_{\text{eligible}}}{N_{\text{confirmed}} + D_{\text{eligible, unconfirmed}}} \]

where \(D_{\text{eligible}}\) is the number of eligible deaths — observed deaths (alert status or final status = “Décédé”) with a positive or unavailable laboratory result — and \(D_{\text{eligible, unconfirmed}}\) is the subset of those deaths that are not also confirmed cases. Exact binomial 95% confidence intervals are computed. HZs with denominator < 5 fall back to the pooled CFR.

Stage 2 — Detection rate from deaths. The detection rate is the ratio of detected confirmed cases to the estimated true case count, where true cases are back-calculated from observed deaths:

\[ \rho_{\text{backcalc}} = \frac{N_{\text{detected}}}{\hat{C}_{\text{true}}} \]

with the true case estimate:

\[ \hat{C}_{\text{true}} = \frac{D_{\text{observed}} \times (1 + r/\beta)^{\alpha}}{\text{CFR}_{\text{backcalc}}} \]

Delay-distribution adjustment. The term \((1 + r/\beta)^{\alpha}\) corrects the right-censoring bias that arises because deaths lag behind case onsets during a growing or declining epidemic. The onset-to-death delay is modelled as Gamma-distributed with:

\[ \alpha = \left(\frac{\mu}{\sigma}\right)^2, \qquad \beta = \frac{\mu}{\sigma^2} \]

where \(\mu = 11.37\) days and \(\sigma = 5.41\) days (literature values for EVD onset-to-death delay). The exponential growth rate \(r\) is estimated per HZ per rolling window. When \(r > 0\) (growing epidemic), the adjustment factor exceeds 1, inflating the estimated true case count to account for deaths that have not yet been observed; when \(r < 0\), it is less than 1.

Confidence intervals on \(\rho_{\text{backcalc}}\) combine the CFR confidence bounds with the growth-rate confidence bounds to produce detection_rate_low (pessimistic) and detection_rate_high (optimistic).

0.5.4 C.4 Combining detection estimates

The two detection estimates are combined into a single rate per HZ:

  1. Validity filter. Only detection rates satisfying \(0 < \rho \leq 1\) are retained. Rates outside this range (e.g., back-calc estimates > 1 from sparse data) are set to missing.

  2. Averaging. The combined detection rate is the arithmetic mean of valid sources:

\[ \rho_{\text{combined}} = \frac{1}{S} \sum_{s \in \{\text{backcalc},\, \text{epilink}\}} \rho_s \]

where \(S\) is the number of valid sources (0, 1, or 2). If neither source is valid, the combined rate is missing and downstream true-case estimates are missing.

  1. True case estimation. Estimated true cases in the recent window:

\[ \hat{C}_{\text{true, recent}} = \frac{C_{\text{detected, recent}}}{\rho_{\text{combined}}} \]

where \(C_{\text{detected, recent}}\) is the count of confirmed/positive cases in the most recent 7-day window. For the most recent window, this count may be replaced by a growth-model projection (predicted_last_count) to mitigate reporting-delay right-censoring.

  1. Source tracking. The output records which methods contributed (detection_rate_source_names: “backcalc”, “epilink”, or “backcalc,epilink”) and the combination status (detection_rate_combined_status: “averaged”, “single_source”, or “no_valid_detection_rate”).

0.5.5 C.5 Rolling-window architecture

Approach C produces time-varying thresholds using non-overlapping windows:

  • Window generation. Non-overlapping 7-day windows are generated backward from the most recent confirmed-case onset date. Each window is identified by a threshold_time_key (its start date) and carries a recent_case_window_start / recent_case_window_end pair (the exposure period) and a threshold_valid_from / threshold_valid_to pair (the period during which the threshold applies).
  • Reporting-delay guard. The last n_copy_last = 1 window copies its growth-rate estimate (and consequently its multiplier estimates) from the preceding window, because the most recent days are subject to right-censoring from notification delays.
  • Pooled fallback. A pooled (all-HZ combined) growth rate is computed for each window date and used when the HZ-specific estimate is unavailable (too few cases, fit failure).
  • Analysis bounds. Windows are bounded by analysis_start_date (max of earliest confirmed-case date, 2026-04-01) and analysis_end_date (min of latest confirmed-case date, today).

0.5.6 C.6 Poisson offset multiplier model

For each HZ and threshold window, a Poisson GLM with log-link is fitted to estimate the alert multipliers \(\beta_c\) (case-alert) and \(\beta_d\) (death-alert):

\[ \log E[A_w] = \log(E_w) + \beta_0 \]

where \(A_w\) is the validated-alert count in epiweek \(w\) (alive alerts for \(\beta_c\), dead alerts for \(\beta_d\)), and \(E_w\) is the expected exposure. The multiplier is \(\beta = \exp(\beta_0)\).

Exposure allocation. The HZ-level total estimated true cases is allocated across epiweeks in proportion to detected confirmed cases:

\[ E_w^{\text{case}} = \hat{C}_{\text{true, recent}} \times \frac{c_w}{\sum_{w} c_w}, \qquad E_w^{\text{death}} = \hat{C}_{\text{true, recent}} \times \text{CFR} \times \frac{c_w}{\sum_{w} c_w} \]

where \(c_w\) is the detected confirmed-case count in epiweek \(w\).

Dispersion correction. Standard errors are scaled by \(\sqrt{\max(1, \phi)}\) where \(\phi = \text{deviance} / \text{df}_{\text{residual}}\) is the dispersion estimate, producing quasi-Poisson-style intervals under over-dispersion.

Fallback. If fewer than min_model_weeks = 2 epiweeks have positive exposure, the GLM is not fitted. A simple rate ratio \(\beta = \sum A_w / \sum E_w\) is used instead, with exact Poisson confidence intervals. If total exposure is zero or non-finite, the multiplier is missing and a pooled multiplier (computed across all HZs from validated alerts over estimated true cases) is substituted at synthesis time.

Interpretation. \(\beta > 1\) means the alert system generates more validated alerts than predicted by the estimated true burden (possibly including non-EVD alerts); \(\beta < 1\) means under-ascertainment relative to estimated true cases.

Threshold construction. The case-derived thresholds combine a non-zero baseline floor (from Approach B) with the multiplier-applied expected count:

\[ T_C^{\text{lower}} = T_B^{\text{baseline}} + \beta_{\text{low}} \times E, \qquad T_C^{\text{upper}} = T_B^{\text{baseline}} + \beta_{\text{high}} \times E \]

where \(T_B^{\text{baseline}}\) is the Approach B baseline alert count (baseline_alive_alerts for cases, baseline_death_alerts for deaths), and \(E\) is the expected count (estimated_true_cases_recent for cases, expected_deaths for deaths).

0.6 Threshold synthesis

The final synthesis table combines the three approaches into a single set of thresholds per HZ and threshold window.

In the implemented code:

  • Alert_case_lower and Alert_case_upper average the Beni benchmark with the case-derived lower and upper thresholds.
  • Alert_death_lower and Alert_death_upper average the baseline mortality threshold, the Beni benchmark, and the case-derived threshold.
  • Central thresholds are then computed as the midpoint between the lower and upper bounds.
  • All numeric threshold columns are rounded to whole numbers before saving.

The script also saves a list of intermediate parameter tables, including CFR, detection, growth, recent cases, multipliers, Rt/SAR, baseline mortality, Beni benchmark summaries, and case-derived threshold components.

2 Glossary — Intermediate parameters (01_intermediate_parameters.rds, English)

The following columns appear in the case-derived component of 01_intermediate_parameters.rds (case_derived_params) and the multiplier table.

  • estimated_true_cases_recent: Estimated true incident cases in the recent 7-day window, computed as detected confirmed cases divided by the combined detection rate.
  • estimated_true_cases_global: Estimated true incident cases across the entire analysis period, computed as cumulative detected cases divided by the combined detection rate.
  • beta_c: Poisson offset multiplier for case (alive) alerts; exp(intercept) from the case-alert GLM fitting validated alive alerts against estimated true cases.
  • beta_c_low: Lower 95% confidence bound for beta_c (dispersion-corrected or exact Poisson).
  • beta_c_high: Upper 95% confidence bound for beta_c.
  • beta_d: Poisson offset multiplier for death alerts; exp(intercept) from the death-alert GLM fitting validated dead alerts against expected deaths.
  • beta_d_low: Lower 95% confidence bound for beta_d.
  • beta_d_high: Upper 95% confidence bound for beta_d.
  • expected_deaths: Expected deaths in the recent window, computed as estimated_true_cases_recent multiplied by the (direct) CFR.
  • expected_secondary: Expected secondary cases, computed as estimated_true_cases_recent multiplied by contacts_per_case (10) and SAR (Rt / 10).
  • detection_rate_adj: Combined detection rate; arithmetic mean of valid epi-link and back-CFR detection estimates (0 < rate <= 1).
  • under_detection_rate: One minus detection_rate_adj.
  • detection_rate_source_names: Which detection methods contributed (“backcalc”, “epilink”, or “backcalc,epilink”).
  • detection_rate_combined_status: How the combined rate was derived (“averaged”, “single_source”, or “no_valid_detection_rate”).
  • cfr_used: CFR used for expected-death calculations; HZ-specific when >= 5 confirmed cases, otherwise the pooled (all-HZ) CFR.
  • cfr_backcalc_used: Back-calculated CFR (eligible deaths / (confirmed + eligible unconfirmed deaths)); used in the back-calculation detection method.
  • r_used: Exponential growth rate used in the delay-adjustment term; HZ-specific estimate or pooled fallback.
  • sar: Secondary attack rate, computed as Rt / contacts_per_case; defaults to 0.1 when missing.
  • pooled_beta_c: Pooled (all-HZ) case-alert multiplier, computed as total validated alive alerts / total estimated true cases; substituted when HZ-specific beta_c is missing.
  • pooled_beta_d: Pooled (all-HZ) death-alert multiplier, computed as total validated dead alerts / total expected deaths; substituted when HZ-specific beta_d is missing.
  • baseline_alive_alerts: Beni benchmark case-alert count scaled to HZ population (Approach B). Previously used as a non-zero floor in Approach C case thresholds; now retained as a reference value only (no longer added to Approach C formulas).
  • baseline_death_alerts: Beni benchmark death-alert count scaled to HZ population (Approach B). Previously used as a non-zero floor in Approach C death thresholds; now retained as a reference value only (no longer added to Approach C formulas).

2.1 Caveats and limitations

  • Population figures are projected from 2024 and may not reflect displacement or local demographic change.
  • The crude mortality rate is applied as a fallback assumption and is not zone-specific.
  • k = 10 contacts per case is a working assumption.
  • The Beni benchmark depends on the definition of low-positivity periods and the quality of the historical dataset.
  • The case-derived thresholds depend on sparse-data estimates and rolling-window model fitting, so uncertainty can be substantial in some HZs.
  • The epi-link method assumes that alert_lien_epidemiologic == "Oui" indicates active case-finding; misclassification of this field biases the detection estimate.
  • The back-CFR method assumes the onset-to-death delay distribution (Gamma, mean 11.37, sd 5.41 days) is correct for this setting; a different delay would change the delay-adjustment factor.
  • The two detection rates are combined by simple unweighted averaging; no precision-weighting or hierarchical model is applied, so a noisy single-source estimate can outweigh a more stable paired estimate.
  • The Poisson offset model assumes weekly true cases can be approximated by proportionally allocating the window total across epiweeks based on detected confirmed-case counts; if detection varied substantially across weeks within a window, this allocation is biased.
  • The script is documentation of the implemented workflow, not a claim that each component is equally precise.
